# V1 - Embedding Supervised Models

This version consumes embeddings generated by the embedding-pretrain stage and trains lightweight supervised models on top of them.

## Purpose

- Reuse the learned representation from pretrain instead of retraining on raw sensor rows.
- Keep the downstream models explicit and easy to swap.
- Start with binary or ternary labels depending on class support in the data.

## Input

- Default label CSV: `D:\AgriFusion-IoT\Backend\Benchmark\fuzzy_logic_basic\dataset\flb_input_with_events.csv`
- Default pretrain checkpoint: latest `pretrain_checkpoint.pt` found under the embedding-pretrain output folders, with backward compatibility for older `tabnet_pretrainer.pt` runs

The downstream stage rebuilds the embedding dataframe from the pretrain checkpoint source schema, then merges labels from the annotated CSV by `timestamp`.

## Label policy

The v1 label policy is based on the aggregated `big_label` field from Layer 1.5 annotations.

- Binary:
  - `normal`
  - `abnormal`
- Ternary:
  - `normal`
  - `environmental_context`
  - `operational_or_intervention`

`auto` mode selects ternary only when the train split has enough support in all three classes and the minority classes are not too sparse compared with the majority class. For the current dataset, binary is the safer default. Ternary remains available when the class balance improves.

## Downstream models

This version trains several models on the embedding:

- `linear_probe`
  Logistic regression baseline.
- `random_forest`
  Tree ensemble on the embedding.
- `hist_gradient_boosting`
  Strong tabular baseline on the embedding.
- `torch_probe`
  Small neural classifier head on the embedding.
- `xgboost` and `lightgbm`
  Optional if the environment already has them installed.

## Output

Each run writes a new folder under:

- `D:\AgriFusion-IoT\Backend\Benchmark\pretrain_supervised\v1\outputs\<DD-MM-YYYY>\<run_name>\`

The report files keep the full timestamped `run_id`; the folder leaf is shortened because the date is already captured by the parent bucket.

Artifacts include:

- `embedding_dataset.csv`
- `label_policy.json`
- `run_config.json`
- `model_metrics.csv`
- `training_report.json`
- model artifacts under `models/`
- `embedding_scaler.pkl`
- `run_status.json`

## Run command

```powershell
python D:\AgriFusion-IoT\Backend\Benchmark\pretrain_supervised\v1\main.py --label-mode auto
```

If you want to pin a specific pretrain checkpoint:

```powershell
python D:\AgriFusion-IoT\Backend\Benchmark\pretrain_supervised\v1\main.py --pretrain-checkpoint D:\AgriFusion-IoT\Backend\Benchmark\pretrain_supervised\pretrain\outputs\<DD-MM-YYYY>\<run_name>\pretrain_checkpoint.pt
```

## Assumptions

- The label row is aligned with the embedding row by chronological ordering.
- The embedding-pretrain checkpoint and the downstream label CSV must share the same `timestamp` keys after cleaning.
- `big_label` is treated as the stable top-level label source for v1 because it reduces the tiny event classes into fewer downstream classes.

## Limits

- This is still an embedding-first downstream pipeline. It does not yet fine-tune the full pretrain backbone end-to-end.
- The annotated event CSV is used only to provide downstream labels, not as the feature source for the encoder.
- Optional XGBoost/LightGBM models are skipped if the libraries are missing.
- If a future fuzzy Layer2 schema changes the feature shape, v2 should be created instead of forcing v1 to absorb the change.
